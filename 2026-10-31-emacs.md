# 1\. What is Emacs?

**Emacs is a highly extensible text editor and programmable working environment.** It began as a family of text editors in the 1970s and evolved into one of the most customizable tools in the Unix and programming world.

Emacs is especially famous for three things\:

- Powerful text editing and keyboard commands.
- Customization using Emacs Lisp, a dialect of Lisp.
- An ecosystem that extends beyond editing code into notes, task management, email, terminals, version control, and more.



Unlike VS Code, which emphasizes a graphical editor extended through plugins, Emacs has a long-standing philosophy of making the editor itself programmable. Users can change its behavior, define commands, and build entire workflows inside it.

Unlike Vim, which emphasizes modal editing, Emacs traditionally uses keyboard shortcuts built around combinations of modifier keys such as `Ctrl` and `Alt`\.

For example\:

- `Ctrl-x Ctrl-s` saves a file.
- `Ctrl-x Ctrl-f` opens a file.
- `Ctrl-g` cancels many commands.
- `Alt-x` invokes a command by name.

These conventions are different from Vim's `i`, `Esc`, `dd`, and `:w` style of interaction.

## 1.1 What can Emacs do?

Emacs can be used for\:

- Editing source code in Java, C, Python, JavaScript, and many other languages.
- Writing documentation and technical notes.
- Managing tasks, calendars, and personal knowledge.
- Working with Git repositories.
- Running shell commands and terminal sessions.
- Searching and manipulating large amounts of text.
- Customizing your environment with Emacs Lisp.

The important idea is that Emacs is not just an editor with many plugins. It is an environment whose behavior can be extensively programmed from within the editor.

# 2\. The history of Emacs

Emacs has a long history closely connected to Lisp, artificial intelligence research, and the development of programmable software tools.



**1970s — Early Emacs**

Emacs emerged at MIT's Artificial Intelligence Laboratory as a collection of editing macros for TECO. Richard Stallman and Guy Steele were among the people involved in its early development.

---



**1984 — GNU Emacs**

Richard Stallman began GNU Emacs as part of the GNU Project. It became an important free-software editor and an example of a large application designed to be extended through its own scripting language.

---



**1990s–2000s — A mature environment**

Emacs developed extensive programming-language support, graphical interfaces, syntax highlighting, completion, version-control integrations, and document-management tools.

---



**2000s onward — Beyond text editing**

Packages such as Org mode and Magit helped make Emacs useful for structured writing, task management, and sophisticated Git workflows in addition to programming.

Emacs is still actively developed. GNU Emacs is the best-known implementation today, although other Emacs variants and related projects exist.

# 3\. The core philosophy: everything is programmable

One of the most important ideas behind Emacs is that **the editor's behavior can be changed by writing programs in Emacs Lisp**\.

Emacs Lisp is a dialect of Lisp designed to support Emacs itself. It lets you define commands, change editing behavior, automate repetitive tasks, and develop extensions.

For example, you can define a command that inserts a greeting\:

```
(defun insert-greeting ()
  "Insert a greeting into the current buffer."
  (interactive)
  (insert "Hello, Emacs!"))
```



Save this code in your Emacs configuration, evaluate it, and invoke the command with `M-x insert-greeting`\.

Here is what the code does\:

- `defun` defines a function.
- `interactive` makes it available as a user-invoked command.
- `insert` inserts text at the current cursor position.
- `M-x` lets you execute a command by its name.

This is a small example, but the same mechanism can be used to automate complex workflows.

## 3.1 Why is this important?

Consider the three editors from your previous questions.

| Editor | Main customization approach |
|--------|--------|
| Vim | Vimscript, settings, mappings, plugins |
| Neovim | Lua, Vimscript, APIs, plugins |
| Emacs | Emacs Lisp, interactive commands, packages |
| VS Code | Settings, keybindings, extensions written mainly in JavaScript/TypeScript |

Emacs has an especially deep relationship between its programming language and the editor itself. Many built-in features are implemented in Emacs Lisp, which means users can inspect, modify, and extend a large part of the environment.

This is one reason Emacs appeals to programmers who enjoy understanding and customizing the tools they use.

# 4\. How Emacs works

There are several concepts worth understanding before you start using Emacs.

## 4.1 Buffers

A **buffer** is the text or working content Emacs is currently managing.

When you open a file, Emacs normally creates a buffer containing that file's contents. But a buffer does not have to correspond to a file.

For example, Emacs can have buffers for\:

- A Java source file.
- A shell session.
- Git status.
- Search results.
- Help documentation.
- A scratch area for experimenting with Lisp.

This is different from thinking of the editor simply as a collection of open file windows.

## 4.2 Major modes

A major mode adapts Emacs to the kind of content you are editing.

Examples include\:

- `java-mode` for Java source code.
- `python-mode` for Python.
- `c-mode` for C.
- `html-mode` for HTML.
- `org-mode` for structured notes and documents.
- `text-mode` for ordinary text.

Different modes can provide their own commands, syntax rules, indentation behavior, and integrations.

## 4.3 Minor modes

Minor modes add optional behaviors without replacing the major mode.

Examples include modes for\:

- Displaying line numbers.
- Highlighting matching parentheses.
- Automatic indentation.
- Spell checking.
- Version-control indicators.
- Language-server integration.

You can combine multiple minor modes to create a customized editing environment.

## 4.4 Windows and frames

Emacs terminology can initially be confusing\:

- A **frame** is roughly a top-level application window.
- A **window** is a pane inside a frame that displays a buffer.

For example, you can split one Emacs frame into two windows, displaying Java source code in one and documentation in the other.

This is useful when navigating large projects or reading code alongside its documentation.

# 5\. Emacs features worth knowing

Emacs has many packages, but a few are particularly important.



**Org mode**

A system for outlining, note-taking, task management, scheduling, and literate programming. You can organize study notes, record Java interview questions, and maintain a learning plan in plain-text files.

---



**Magit**

A popular Git interface for Emacs. It provides interactive staging, commits, branch management, history inspection, and other Git operations.

---



**Shell and terminal integration**

Emacs can run shell commands and provide interactive shell or terminal sessions. This is useful when you work extensively in Linux.

---



**Programming and LSP**

Packages such as `eglot` and `lsp-mode` connect Emacs to language servers, enabling diagnostics, code navigation, completion, and other programming features.

For Java development, Emacs can work with Maven, JUnit, Java language servers, and debugging tools. However, you need to configure the relevant packages and external tools, and the overall experience may require more setup than IntelliJ IDEA.

# 6\. Essential Emacs keyboard shortcuts

Emacs uses a notation that you'll see throughout its documentation.

- `C-x` means hold `Ctrl` and press `x`\.
- `M-x` means hold `Alt` and press `x`; `M` stands for Meta.
- `C-g` means `Ctrl+g`\.

If your keyboard or terminal handles Meta differently, `Esc` followed by a key can often serve as an alternative.

| Shortcut | Action |
|--------|--------|
| `C-x C-f` | Open a file |
| `C-x C-s` | Save the current file |
| `C-x C-c` | Exit Emacs |
| `C-g` | Cancel a command |
| `C-s` | Search forward |
| `C-r` | Search backward |
| `C-space` | Set the mark to begin selecting text |
| `M-w` | Copy the selected region |
| `C-w` | Cut the selected region |
| `C-y` | Paste (yank) text |
| `C-/` | Undo |
| `C-x 2` | Split the current window horizontally |
| `C-x 3` | Split the current window vertically |
| `C-x o` | Switch to another window |
| `M-x` | Execute a command by name |

The terminology differs slightly from Vim. For example, Emacs calls its paste operation *yank*, whereas Vim uses `p` in Normal mode.

### A quick exercise

Start Emacs and try the following\:

1. Press `C-x C-f` and enter `~/practice.txt`\.
2. Type some text.
3. Press `C-x C-s` to save.
4. Press `C-s` to search for a word.
5. Press `C-x C-c` to exit.

Once these commands become familiar, you can gradually learn more advanced features.

# 7\. Installing Emacs on Ubuntu

Emacs is available in Ubuntu's package repositories.

Open your terminal and run\:

```
sudo apt update
sudo apt install emacs
```



To launch Emacs\:

```
emacs
```



To open a particular file\:

```
emacs Student.java
```



To launch it without a graphical window\:

```
emacs -nw
```



The `-nw` option runs Emacs in the terminal.

You can also check the installed version\:

```
emacs --version
```



The exact version available depends on your Ubuntu release and configured repositories.

## 7.1 Your first configuration

Emacs normally reads user configuration from\:

```
~/.emacs
```



or\:

```
~/.emacs.d/init.el
```



Modern configurations commonly use `~/.emacs.d/init.el`, though newer setups may use `~/.config/emacs/init.el`\.

A simple starting configuration is\:

```
;; Display line numbers
(global-display-line-numbers-mode 1)

;; Highlight matching parentheses
(show-paren-mode 1)

;; Enable automatic indentation behavior
(electric-indent-mode 1)

;; Use spaces instead of tabs for indentation
(setq-default indent-tabs-mode nil)
```



You don't need to learn Emacs Lisp deeply before using Emacs. Begin with a few settings, then customize your environment as your needs grow.

# 8\. Emacs vs Vim vs Neovim vs VS Code

Let's compare their underlying design philosophies.

| Dimension | Emacs | Vim | Neovim | VS Code |
|--------|--------|--------|--------|--------|
| Editing style | Modifier-key commands | Modal | Modal | Conventional graphical editing by default |
| Primary customization | Emacs Lisp | Vimscript | Lua and Vimscript | Settings and extensions |
| Terminal usage | Excellent | Excellent | Excellent | Primarily graphical, with an integrated terminal |
| Notes and task management | Particularly strong with Org mode | Mainly through plugins or external tools | Mainly through plugins or external tools | Mainly through extensions |
| Lightweight text editing | Capable, but highly configurable | Excellent | Excellent | More resource-intensive in general |
| Programming environment | Highly extensible | Plugin-based | Plugin-based, modern APIs | Extension-based |
| Learning curve | Steep | Steep | Steep | Gentler initially |

Neither Emacs nor Vim is objectively better. They embody different ideas about how a programmer should interact with a computer.

Vim emphasizes composing efficient editing operations. Emacs emphasizes an extensible environment in which the user can program the editor itself.

# 9\. Is Emacs a good choice for your Java backend learning?

Since you are studying Java backend development on Linux, I would separate two goals.

**Goal A: Learn Java and backend engineering.**

Use IntelliJ IDEA as your primary Java IDE if you want integrated Maven support, refactoring, debugging, testing, and Spring Boot development.

**Goal B: Learn Linux tools and build a customizable working environment.**

Emacs is worth exploring if you enjoy the idea of writing your own editor commands, maintaining structured technical notes, and managing development tasks in one place.

For example, you could create an Org mode file for your Java studies\:

```
* Java Backend Learning

** Java Fundamentals
*** TODO Review collections
*** TODO Practice exception handling

** Maven
*** TODO Understand pom.xml
*** TODO Practice dependency management

** Spring Framework
*** TODO Learn dependency injection
*** TODO Practice ApplicationContext

** Spring Boot
*** TODO Create a REST API
*** TODO Write controller tests
```



This file is plain text, but Emacs can turn it into an interactive outline and task-management system.

That is one of Emacs's most distinctive advantages: your notes, tasks, code, and automation can live in a single programmable environment.

## My final recommendation

- Choose **Vim or Neovim** if your main goal is efficient keyboard-based text editing and Linux command-line work.
- Choose **Emacs** if you want a highly programmable environment that combines editing, notes, task management, and development tools.
- Choose **VS Code** if you want a convenient general-purpose graphical code editor.
- Choose **IntelliJ IDEA** for a more integrated Java backend development experience.

You don't need to master all four. For your current learning path, I would focus on Java and backend development first, learn basic Vim or Neovim for Linux work, and explore Emacs if its programmable-environment philosophy interests you.
