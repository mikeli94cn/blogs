You can use `scp`**&#x20;(Secure Copy Protocol)** to securely transfer files from your Dell laptop (Ubuntu 24.04) to your Debian 13 server over SSH.

Since both computers run Linux, `scp` is a convenient solution. It uses SSH for authentication and encryption.

## **1. Check the prerequisites**

**Dell Latitude E6440**

Ubuntu 24.04 · Source computer

SCP over SSH · Local network

**Lenovo Debian 13 Server**

Destination computer · SSH port 22

On your Debian server, check whether SSH is running:

```
sudo systemctl status ssh
```

If SSH is not installed:

```
sudo apt update
sudo apt install openssh-server
sudo systemctl enable --now ssh
```

Find the server's IP address:

```
hostname -I
```

For example, suppose your Debian server has the following details:

```
IP:       192.168.1.100
Username: mikeli
```

Replace these example values with your actual server details.

On your Dell laptop, check that `scp` is available:

```
scp -V
```

Note: Some `scp` versions don't support `-V`. You can instead use:

```
command -v scp
```

If it isn't installed:

```
sudo apt install openssh-client
```

## **2. Transfer a single file**

Run this command **on your Dell laptop**:

```
scp ~/Documents/test.txt mikeli@192.168.1.100:/home/mikeli/
```

Explanation:

| Component              | Meaning                |
| ---------------------- | ---------------------- |
| `scp`                  | Secure copy command    |
| `~/Documents/test.txt` | Source file on Dell    |
| `mikeli`               | Debian server username |
| `192.168.1.100`        | Debian server IP       |
| `/home/mikeli/`        | Destination directory  |

The server may ask for your SSH password. Once authenticated, the file will be transferred.

## **3. Transfer an entire directory**

Suppose you want to transfer a Java Spring Boot project from your Dell laptop to your Debian server.

Use `-r` for recursive copying:

```
scp -r ~/code/student-management \
  mikeli@192.168.1.100:/home/mikeli/
```

This copies the entire `student-management` directory, including its files and subdirectories.

## **4. Transfer a Spring Boot JAR file**

For your Java backend development, this is especially useful.

Suppose your compiled application is:

```
~/code/student-management/target/student-management-0.0.1-SNAPSHOT.jar
```

Transfer it to your Debian server:

```
scp ~/code/student-management/target/*.jar \
  mikeli@192.168.1.100:/home/mikeli/
```

Then connect to the server:

```
ssh mikeli@192.168.1.100
```

Run the application:

```
java -jar student-management-0.0.1-SNAPSHOT.jar
```

This assumes Java is installed on the Debian server.

## **5. Transfer files from Debian back to Dell**

You can also download files from your server.

Run on your Dell laptop:

```
scp mikeli@192.168.1.100:/home/mikeli/test.txt \
  ~/Downloads/
```

The syntax is:

```
scp SOURCE DESTINATION
```

The remote side is identified by `username@host:path`.

## **6. Useful SCP options**

| Option    | Description                                 |
| --------- | ------------------------------------------- |
| `-r`      | Copy directories recursively                |
| `-P 2222` | Use SSH port 2222 instead of 22             |
| `-p`      | Preserve modification times and permissions |
| `-C`      | Enable compression                          |
| `-v`      | Display debugging information               |
| `-i`      | Specify an SSH private key                  |
| `-O`      | Use legacy SCP protocol instead of SFTP     |

For example, to copy a large directory using compression:

```
scp -rC ~/code/myproject \
  mikeli@192.168.1.100:/home/mikeli/
```

## **7. SCP vs rsync: which is better?**

Since you frequently work with Java projects, Docker, and Linux servers, I recommend learning both `scp` and `rsync`.

| Feature                      | SCP       | rsync         |
| ---------------------------- | --------- | ------------- |
| Single file transfer         | Excellent | Excellent     |
| Directory transfer           | Yes       | Yes           |
| Incremental synchronization  | No        | Yes           |
| Resume interrupted transfers | Limited   | Yes           |
| SSH encryption               | Yes       | Yes, with SSH |
| Deployment workflows         | Basic     | More flexible |

For example, synchronize a project directory:

```
rsync -avz --progress \
  ~/code/student-management/ \
  mikeli@192.168.1.100:/home/mikeli/student-management/
```

After the first transfer, `rsync` normally sends only changed files, making subsequent transfers more efficient.

## **8. Troubleshooting**

If you encounter:

**Connection refused**

Check the SSH service on Debian:

```
sudo systemctl status ssh
```

**Connection timed out**

Check connectivity from Dell:

```
ping 192.168.1.100
```

Also verify the server's IP address and firewall rules.

**Permission denied**

Make sure the destination directory is writable by your Debian user. For example, `/home/mikeli/` is generally suitable for that account.

**Recommendation for your setup:** Use `scp` for transferring individual files, especially compiled Spring Boot JAR files. Use `rsync` when synchronizing entire Java projects or deployment directories.

One additional improvement is to configure **SSH public-key authentication** between your Dell laptop and Debian server. This allows secure transfers without repeatedly entering your server password.
