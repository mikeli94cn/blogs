# What is Event Programming?

**Event programming** (also called **event-driven programming**) is a programming paradigm where the flow of a program is determined by **events** rather than by a fixed sequence of instructions.

In traditional programming, the program usually controls the execution order:

```
Start
 |
Read input
 |
Process data
 |
Output result
 |
End
```

In event-driven programming, the program waits for something to happen, and then reacts:

```
              Event occurs
                   |
                   v
             Event Handler
                   |
                   v
             Execute logic
```

The program is organized around:

* **Events** → things that happen
* **Event sources** → things that generate events
* **Event handlers / callbacks** → code that reacts to events
* **Event loop** → mechanism that waits for and dispatches events

---

# 1. What is an Event?

An **event** is a notification that something has happened.

Examples:

## User events

A user interacts with a program:

* Mouse click
* Keyboard press
* Touch screen gesture
* Drag and drop

Example:

```
User clicks "Save" button
          |
          v
ButtonClick event
          |
          v
saveFile() executes
```

---

## System events

Generated by the operating system:

* Timer expires
* Network packet arrives
* File becomes available
* Device sends data

Example:

```
Network receives data
          |
          v
NetworkEvent
          |
          v
Process received message
```

---

## Application events

Generated inside software:

* Order created
* Payment completed
* User registered

Example:

```
OrderCreatedEvent
          |
          v
Send confirmation email
Update inventory
Create invoice
```

---

# 2. Basic Structure of Event Programming

An event-driven system usually contains four parts:

## 1. Event Producer

Something creates an event.

Example:

```
Mouse
 |
 v
MouseClick Event
```

or:

```
Database
 |
 v
DataChanged Event
```

---

## 2. Event Queue

Events are stored temporarily.

Example:

```
+----------------+
| Click Event    |
| Key Event      |
| Timer Event    |
+----------------+
        |
        v
```

---

## 3. Event Loop

The program continuously checks for events:

```
while(true)
{
    event = getNextEvent();

    handle(event);
}
```

The event loop is the heart of event-driven systems.

---

## 4. Event Handler

The handler contains the reaction logic.

Example:

```java
button.addActionListener(event -> {
    System.out.println("Button clicked");
});
```

When the click happens:

```
Click Event
     |
     v
ActionListener
     |
     v
Print message
```

---

# 3. Event Programming vs Traditional Programming

## Traditional procedural programming

The programmer defines the order:

```c
main()
{
    readInput();

    calculate();

    printResult();
}
```

Execution:

```
Step 1
 |
Step 2
 |
Step 3
```

The program is in control.

---

## Event programming

The environment controls the order:

```java
onButtonClick()
{
    save();
}

onTimer()
{
    update();
}

onNetworkMessage()
{
    process();
}
```

Execution:

```
Waiting...

        Event happens

              |
              v

       Execute handler
```

The outside world is in control.

---

# 4. Why Did Event Programming Appear?

Early computers mostly used **batch processing**.

Example:

```
Input file
    |
    v
Program runs
    |
    v
Output file
```

The computer processed jobs sequentially.

---

With interactive systems, this became insufficient.

People wanted:

* graphical interfaces
* mouse interaction
* real-time response
* network communication

For example:

A GUI program cannot predict:

```
User clicks at 10:05:23
User clicks again at 10:05:27
User drags window at 10:05:31
```

Therefore:

```
Wait → Detect event → React
```

became the natural model.

# 7. Event Loop: The Core Principle

The most important idea is:

> A program spends most of its time waiting, and reacts only when events arrive.

Example:

```
              +--------------+
              | Event Queue  |
              +--------------+
                     |
                     v
              +--------------+
              | Event Loop   |
              +--------------+
                     |
       +-------------+-------------+
       |             |             |
       v             v             v

  Mouse Event   Network Event  Timer Event

       |
       v

 Event Handler
```

This design allows one thread to manage many activities.

---

# 8. Event Programming and Concurrency

Event programming is closely related to concurrency.

Traditional thread model:

```
Thread 1 → Client A
Thread 2 → Client B
Thread 3 → Client C
```

Event model:

```
Single Thread

Event Loop
    |
    +-- Client A event
    |
    +-- Client B event
    |
    +-- Client C event
```

This is why systems like:

* Node.js
* Netty
* Nginx

can handle many connections efficiently.

# 11. Advantages of Event Programming

## 1. Good for interactive applications

Natural for:

* GUI
* games
* mobile apps

---

## 2. Efficient resource usage

A single event loop can handle many tasks.

---

## 3. Loose coupling

Components communicate through events:

```
Producer
    |
    v
 Event
    |
    v
Consumer
```

The producer does not know who consumes the event.

---

## 4. Scalable systems

Used in:

* cloud systems
* distributed systems
* streaming platforms

---

# 12. Disadvantages

## 1. Harder control flow

Traditional:

```
call A()
 call B()
  call C()
```

Easy to follow.

Event:

```
event happens somewhere

who handles it?

when does it run?

```

More difficult.

---

## 2. Debugging complexity

Events may travel through many components:

```
User Action
 |
Event Bus
 |
Service A
 |
Service B
 |
Database
```

---

## 3. Event ordering problems

Example:

```
PaymentCompleted

arrives before

OrderCreated
```

Distributed systems must handle this.

# Summary

**Event programming is a programming paradigm where programs are built around responding to events instead of following a fixed sequence of instructions.**

Its core idea is:

```
Wait for event
       |
       v
Detect event
       |
       v
Run handler
       |
       v
Continue waiting
```

It became essential because modern computers are interactive, connected, and distributed. Today, GUI systems, web applications, network servers, operating systems, and cloud architectures all rely heavily on event-driven programming.
