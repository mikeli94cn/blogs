# how to set terminal proxy
To make these proxy settings permanent in Ubuntu, you need to add them to your shell's configuration file. Since Ubuntu's default shell is Bash, you should add them to your ~/.bashrc file.

Open your terminal and run the following steps:

## Step 1: Open your configuration file

Open your ~/.bashrc file  your preferred text editor:
```bash
vim ~/.bashrc
```

## Step 2: Add the proxy configurations

Scroll to the very bottom of the file and paste the following lines. Note that for socks configurations, terminal tools typically look for the ALL_PROXY or all_proxy variables:
```bash
# Permanent VPN Proxy Configuration for Codex CLI
export http_proxy="http://127.0.0.1:10809"
export https_proxy="http://127.0.0.1:10809"
export HTTP_PROXY="http://127.0.0.1:10809"
export HTTPS_PROXY="http://127.0.0.1:10809"
export all_proxy="socks5://127.0.0.1:10808"
export ALL_PROXY="socks5://127.0.0.1:10808"
export no_proxy="localhost,127.0.0.1,127.0.0.0/8,::1"
export NO_PROXY="localhost,127.0.0.1,127.0.0.0/8,::1"
```
(Adding both lowercase and uppercase variations ensures compatibility, as different CLI tools look for different cases).

## Step 3: Save and Exit

1. Press :wq to save the file and exit.

## Step 4: Apply the changes

To make the changes take effect immediately in your current terminal window without restarting it, run:
```bash
source ~/.bashrc
```

💡 Quick Verification

You can double-check that the system registered your settings by printing one of the variables:
```bash
echo $https_proxy
```

```bash
curl -I https://google.com
```
If it returns http://127.0.0.1:10809, your permanent setup is complete and Codex CLI will now route through your VPN automatically every time you open a terminal.



# how to prevent webrtc leak
To prevent a WebRTC leak, you must either use a premium VPN with built-in WebRTC protection or manually disable or restrict WebRTC in your browser settings. 
Because WebRTC is built directly into browser code to handle video and audio streams, it can bypass standard VPN configurations and expose your real public or local IP address. 

🛡️ Method 1: Use a Leak-Preventing VPN

The easiest way to stop leaks without breaking video-calling websites is to use a reliable VPN provider. 
* Enable WebRTC Protection: Top-tier providers like NordVPN or Surfshark feature native WebRTC leak blocking inside their desktop apps or browser extensions.
* Route Traffic: These VPNs force WebRTC requests through an encrypted tunnel, masking your real IP with the VPN server's IP. 

🌐 Method 2: Fix it in Your Browser Settings

If your VPN doesn't block leaks, or you aren't using one, configure your browser directly. Note that completely disabling WebRTC will break web-based calling tools like Google Meet or Discord. 

Mozilla Firefox (Full Disable)

Firefox is the easiest browser to fully secure because it has a native toggle. 
1. Type about:config into the address bar and press Enter.
2. Click "Accept the Risk and Continue".
3. Search for media.peerconnection.enabled.
4. Double-click the result to change its value from true to false. 

Google Chrome (Requires Extension)

Google Chrome does not have a built-in menu setting to disable WebRTC. You must use a privacy extension: 
* Alternatively, use community-trusted extensions like WebRTC Control or WebRTC Leak Prevent to completely toggle the protocol off.
* Popular ad-blockers like uBlock Origin also have an option in their settings panel to "Prevent WebRTC from leaking local IP addresses".

Brave

Brave has built-in routing controls that block leaks by default while keeping features functional. 
1. Go to Settings > Privacy and security.
2. Find WebRTC IP handling policy.
3. Change it to Disable non-proxied UDP. 

Microsoft Edge

1. Type about:flags or edge://flags into the address bar.
2. Search for "Anonymize local IPs exposed by WebRTC".
3. Change the setting to Enabled. 

Apple Safari

1. Open Preferences > Advanced and check "Show Develop menu in menu bar".
2. Click Develop in the top menu bar.
3. Navigate to WebRTC and uncheck "Enable Legacy WebRTC API". 

🧪 How to Test for Leaks

Once you have applied a fix, verify it works using these steps: 
1. Disconnect your VPN and visit a tool like BrowserLeaks WebRTC Test or IPLeak.net. Note down the IP address shown.
2. Turn your VPN back on and refresh the test page.
3. If the "WebRTC IP Address" section still displays your real ISP-provided IP address (instead of the VPN's IP or blank/local mDNS text), your browser is still leaking.
